# 05.01. Проверка интерактивных возможностей

## Цель

Определить, какие реальные запросы Codex и используемых скиллов можно безопасно обработать через HITL.

## Зависимости и границы

Зависит от 02.01, 02.05, 02.10 и этапа 04. Входит инвентаризация входящих запросов, ответов и подтверждённых ограничений. Реализация UI и политика разрешений не входят.

## Последовательность реализации

1. Взять версию и профиль протокола, подтверждённые в 02; подготовить отдельный тестовый репозиторий.
2. Для каждого требуемого сценария зафиксировать тип запроса, correlation/request handle, допустимые ответы, terminal-событие и поведение при отказе.
3. Проверить вопросы с текстом, одиночным и множественным выбором и разрешения там, где целевой runtime действительно их предоставляет. Сценарии скиллов проверить совместно с 08.
4. Отделить runtime request от бизнес-утверждения результата и запроса вмешательства после ошибки: последние могут возникать в оркестраторе.
5. Описать неподдерживаемые и неизвестные payload. Не преобразовывать неизвестный запрос в автоматическое разрешение.

## Тестовые сценарии

| Сценарий | Ожидаемый результат |
|---|---|
| Поддерживаемый реальный запрос | Есть transcript с типом, ответом и подтверждённым исходом. |
| Неизвестный тип или вариант ответа | Запрос заблокирован с диагностикой; действие не разрешено молча. |
| Скилл задаёт вопрос вне структурированного канала | Ограничение зафиксировано; поддержка не заявлена. |

## Критерии приёмки

- [ ] Матрица запросов указывает источник доказательства и версию runtime.
- [ ] Для обязательных механизмов есть реальные сценарии либо явный блокирующий пробел.
- [ ] Список нормализованных типов не шире подтверждённых возможностей.
- [ ] Неизвестные запросы не ведут к автоматическому продолжению.

## Ожидаемые артефакты

Матрица интерактивных возможностей, обезличенные transcripts, перечень открытых вопросов.

## Открытые вопросы

Какие вопросы скиллов являются структурированными runtime requests, а какие видны только в тексте turn? Ответ устанавливается испытанием, а не предположением.
