# Этап 05 — Human-in-the-Loop

Шесть самостоятельных заданий на реализацию. Основание: [исходный эпик](05-human-in-the-loop.md) и [требования проекта](../../project.md). Статус всех заданий — план; совместимость с фактическим Codex и скиллами предстоит подтвердить.

| Подэтап | Задание |
|---|---|
| 05.01 | [Проверка интерактивных возможностей](05.01-interaction-compatibility.md) |
| 05.02 | [Модель запроса и жизненный цикл](05.02-request-lifecycle.md) |
| 05.03 | [Политика разрешений и утверждений](05.03-permission-and-approval-policy.md) |
| 05.04 | [Ответ и защита от дублей](05.04-answer-dispatch.md) |
| 05.05 | [API ожидающих запросов](05.05-hitl-api.md) |
| 05.06 | [Интеграционные сценарии](05.06-integration-tests.md) |

Порядок: 05.01 задаёт подтверждённый набор runtime-запросов; 05.02–05.03 можно прорабатывать параллельно; затем 05.04–05.06. Черновик контракта ответа нужен до реализации API. Для неподтверждённого типа запроса действует остановка с диагностикой.

Границы: этап 02 доставляет runtime request и принимает ответ через адаптер; этап 03 хранит состояния и события; этап 04 связывает execution с session. Этап 05 принимает решение пользователя и управляет жизненным циклом HITL. Бизнес-утверждение плана принадлежит 06, формы — 10, восстановление после сбоя — 11. Проверку поведения конкретных скиллов координировать с 08.

Критерии каждого файла закрываются ссылками на тесты и отчёты. Наличие плана не означает, что механизм реализован или проверен.
