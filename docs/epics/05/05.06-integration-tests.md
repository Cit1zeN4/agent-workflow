# 05.06. Интеграционные сценарии HITL

## Цель

Подтвердить, что вопросы и решения проходят всю цепочку runtime → хранилище → API → runtime или бизнес-этап.

## Зависимости и границы

Зависит от 05.01–05.05. Реальная проверка использует профиль 02.10 и скиллы 08; полный workflow и упаковка относятся к 12.

## Последовательность реализации

1. Выполнить детерминированные тесты с fake adapter для каждого поддержанного типа запроса, отказа, истечения, дубля и disconnect.
2. Проверить атомарность хранения, порядок событий и получение pending после переподключения UI-клиента.
3. В отдельном тестовом репозитории запустить реальные интерактивные сценарии целевого Codex. Проверить фактический ответ и завершение, не только успешный HTTP-статус.
4. Запустить вопросы используемых скиллов совместно с 08 и записать наблюдаемый канал. Неподтверждённый механизм пометить blocked/not-run.
5. Сформировать отчёт с версиями, transcripts без секретов и ссылками на каждое доказательство.

## Тестовые сценарии

| Сценарий | Ожидаемый результат |
|---|---|
| Текст/выбор/разрешение | Есть подтверждённый исход для каждого реально поддержанного типа. |
| Отказ и конфликт | Действие не выполняется дважды; причина видна пользователю. |
| Обрыв runtime при ожидании | Запрос не разрешается автоматически и помечен для сверки. |

## Критерии приёмки

- [ ] Fake suite проверяет типы, гонки и ошибки.
- [ ] Обязательные реальные сценарии имеют pass и evidence; blocked/not-run не считается pass.
- [ ] Вопросы скиллов проверены совместно с 08 либо отмечены как незакрытый блокер.
- [ ] Отчёт различает контрактный тест и фактическое поведение runtime.

## Ожидаемые артефакты

Fixtures, интеграционные тесты и acceptance report HITL.
