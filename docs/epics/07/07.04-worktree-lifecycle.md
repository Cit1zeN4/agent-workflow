# 07.04. Ветка и Git worktree

## Цель

Создавать изолированный рабочий каталог для run или ticket, не изменяя основную рабочую копию.

## Зависимости и границы

Зависит от 07.01–07.03 и Git for Windows из целевой конфигурации. Выбор соответствия run/ticket workspace согласовать с 06/09. Сбор diff и commit metadata принадлежит 09.

## Последовательность реализации

1. Определить уникальные и безопасные имена ветки и каталога, связь с projectId/runId/ticketId, а также правило повторного вызова.
2. Перед созданием проверить исходный repo, доступность базового ref и отсутствие конфликтующих branch/worktree.
3. Создать ветку и worktree через Git с аргументами, переданными без shell-интерполяции. При частичном сбое записать созданные ресурсы для ручной или безопасной компенсации.
4. Сохранить связь с workspace до передачи cwd адаптеру 02. Проверить, что run использует только утверждённый каталог.
5. Повторное создание должно вернуть существующий подтверждённый workspace или явный конфликт, не перезаписывая файлы.

## Тестовые сценарии

| Сценарий | Ожидаемый результат |
|---|---|
| Новый run | Ветка и worktree существуют, основная рабочая копия без изменений. |
| Повтор того же запроса | Нет второй ветки/потери данных. |
| Имя уже занято другим worktree | Объяснимый конфликт без разрушения чужого ресурса. |

## Критерии приёмки

- [ ] Workspace связан с единственным владельцем и сохраняется.
- [ ] Основная ветка и исходный рабочий каталог не меняются.
- [ ] Частичный сбой оставляет диагностируемый статус.
- [ ] cwd для 02 передаётся только из подтверждённого workspace.

## Ожидаемые артефакты

Менеджер worktree, схема владения, интеграционные Git-тесты.

## Открытые вопросы

Нужен один worktree на run или отдельный на ticket? Решить совместно с 09, учитывая последовательные изменения и обзор diff.
