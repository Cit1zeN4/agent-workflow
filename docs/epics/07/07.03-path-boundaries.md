# 07.03. Границы путей и доступа

## Цель

Не допускать чтения и изменения файлов вне выбранного проекта через операции Project Manager.

## Зависимости и границы

Зависит от 07.01–07.02 и ограничений безопасности 01. Это политика операций приложения. Git worktree не является полноценным security sandbox для команд агента; runtime-права и разрешения принадлежат 02/05.

## Последовательность реализации

1. Для каждой операции определить допустимый корень: repo, workspace root или конкретный worktree.
2. Канонизировать путь перед проверкой принадлежности; учитывать Windows drive, регистр, разделители, относительные сегменты и link/junction.
3. Проверять итоговый resolved path непосредственно перед файловой операцией; не доверять только сохранённому пользовательскому пути.
4. Не принимать произвольную команду или путь из браузера как инструкцию выполнить системное действие.
5. Описать отказ для выхода за границу и журналировать безопасные метаданные без лишних содержимых файлов.

## Тестовые сценарии

| Сценарий | Ожидаемый результат |
|---|---|
| Путь через .. или иной drive | Операция отклонена. |
| Link/junction ведёт наружу | Проверка обнаруживает выход за допустимый корень. |
| Допустимый файл внутри worktree | Операция проходит и связана с проектом. |

## Критерии приёмки

- [ ] Каждая файловая операция имеет определённый допустимый корень.
- [ ] Обход через нормализацию и ссылки покрыт тестами.
- [ ] Браузер не получает универсальный command/file API.
- [ ] Документация не называет worktree sandbox команд агента.

## Ожидаемые артефакты

Политика путей, общая функция проверки и Windows-тесты.

## Открытые вопросы

Какие операции должны допускать внешний каталог артефактов? Добавлять исключения только по конкретной необходимости.
