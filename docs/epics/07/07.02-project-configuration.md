# 07.02. Конфигурация проекта

## Цель

Хранить подключённые проекты и их настройки после перезапуска приложения.

## Зависимости и границы

Зависит от 07.01 и Persistence Layer 03. Настройка скиллов принадлежит 08; история runs — 06 и 03.

## Последовательность реализации

1. Определить projectId, канонический repo path, отображаемое имя, workspace root и параметры, нужные MVP. Не хранить секреты в обычной конфигурации.
2. Перед сохранением повторять проверку 07.01, чтобы изменение пути между выбором и записью не регистрировалось молча.
3. Определить операции подключения, чтения списка, обновления разрешённых настроек и отключения. Для повторного подключения того же repo задать идемпотентную семантику.
4. После restart повторно проверить доступность repo и показывать изменившееся состояние, не удаляя запись автоматически.
5. Описать контракт локального API до реализации и примеры ответов/ошибок для UI 10.

## Тестовые сценарии

| Сценарий | Ожидаемый результат |
|---|---|
| Подключение и restart | Проект остаётся в списке с тем же ID. |
| Повторное подключение того же пути | Не возникает неразличимых дублей. |
| Repo удалён извне | Запись сохраняется, но помечена недоступной с причиной. |

## Критерии приёмки

- [ ] Конфигурация и идентификаторы переживают restart.
- [ ] API различает invalid path, conflict и временную недоступность.
- [ ] Подключение не меняет рабочую ветку проекта.
- [ ] Операции ограничены выбранным projectId.

## Ожидаемые артефакты

Схема конфигурации, репозиторий данных, локальный API-контракт и контрактные тесты.

## Открытые вопросы

Что делать при внешнем перемещении repo? Для MVP безопасен явный повторный выбор пути пользователем.
