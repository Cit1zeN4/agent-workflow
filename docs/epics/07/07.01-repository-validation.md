# 07.01. Проверка локального проекта

## Цель

Подключать только доступные локальные Git-репозитории и объяснять причину отказа.

## Зависимости и границы

Зависит от каркаса 01. Входит проверка выбранного пользователем каталога и исходного Git-состояния. Создание worktree относится к 07.04; локальный API оформляется совместно с 07.02.

## Последовательность реализации

1. Принимать путь как данные, без подстановки в командную строку. Определить форму выбора каталога для одного локального пользователя.
2. Нормализовать и канонизировать путь, проверить существование, тип, доступность и ожидаемую область проекта.
3. Проверить Git-репозиторий, top-level, текущую ветку, статус и возможность операций, необходимых MVP. Отличить bare repo, вложенный repo и обычную директорию.
4. Вернуть структурированную диагностику без изменения файлов и Git.
5. Зафиксировать исходный snapshot для сравнения после создания worktree.

## Тестовые сценарии

| Сценарий | Ожидаемый результат |
|---|---|
| Действующий локальный repo | Подключение возможно, показаны исходные сведения. |
| Нет Git или доступа | Понятный отказ без частичной регистрации. |
| Путь с пробелами/Unicode | Проверка корректна, команда не интерпретирует текст как параметры. |

## Критерии приёмки

- [ ] Ошибочные пути и Git-состояния различаются.
- [ ] Проверка не изменяет репозиторий.
- [ ] Путь обрабатывается без shell-интерполяции.
- [ ] Результат годится для решения о подключении проекта.

## Ожидаемые артефакты

Валидатор проекта, типизированная диагностика и тестовые репозитории.

## Открытые вопросы

Разрешать ли подключение worktree как самостоятельного проекта? Определить, чтобы избежать двойного владения ресурсами.
