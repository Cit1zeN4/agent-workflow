# 07.05. Освобождение ресурсов и проверки

## Цель

Безопасно завершать владение workspace и подтвердить поведение на целевой Windows-конфигурации.

## Зависимости и границы

Зависит от 07.01–07.04. Этап 09 решает, когда Git-результаты приняты; 11 сверяет состояние после сбоя. Очистка не равна автоматическому удалению пользовательских изменений.

## Последовательность реализации

1. Перед освобождением проверить активные executions, Git status, commits, связь worktree с project/run и фактический путь.
2. Для чистого подтверждённого workspace описать операцию удаления worktree и судьбу ветки. Для изменённого или неопределённого состояния предложить сохранение/ручное решение.
3. Не удалять каталог, если его ownership или resolved path не подтверждены.
4. Проверить работу на Windows: пробелы/Unicode, занятые файлы, отсутствующий repo, конфликт ветки и повторная операция.
5. Сформировать отчёт с Git-версиями, тестами, оставшимися ресурсами и ограничениями.

## Тестовые сценарии

| Сценарий | Ожидаемый результат |
|---|---|
| Чистый завершённый worktree | Освобождается по подтверждённой операции. |
| Незакоммиченные изменения | Содержимое сохраняется, требуется явное решение. |
| Каталог исчез или перенаправлен | Нет удаления другого пути; статус помечен для сверки. |

## Критерии приёмки

- [ ] Удаление требует подтверждённого владения и безопасного состояния.
- [ ] Изменённый worktree не теряется автоматически.
- [ ] Ошибки файловых блокировок и повторы дают явный результат.
- [ ] Windows-интеграционные тесты подтверждают создание, работу и безопасную очистку.

## Ожидаемые артефакты

Политика освобождения, Git-тесты и acceptance report.

## Открытые вопросы

Когда удалять ветку после review и какие изменения считать принятыми? Согласовать с политикой 09.
