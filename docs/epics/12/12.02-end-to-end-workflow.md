# 12.02. Полный E2E workflow

> Статус: план реализации; проверки не выполнялись.

## Цель

Проверить полный пользовательский путь MVP через Web UI на тестовом Git-репозитории.

## Зависимости и границы

**Зависимости:** 12.01 и готовность 01–10. Входит: реальный workflow, HITL, артефакты, tickets, Git и история. Не входит: утверждение совместимости по fake runtime или точному тексту ответа модели.

## Последовательность реализации

1. Через UI подключить тестовый репозиторий, выполнить первоначальную настройку скиллов и создать run.
2. Пройти уточнение требований, spec и создание tickets; проверить артефакты и реальные интерактивные запросы.
3. Утвердить план через предусмотренный HITL-путь и запустить два зависимых tickets; второй не должен стартовать раньше первого.
4. Проверить изменения в worktree, commit metadata, code review и retrospective; убедиться, что push/merge не выполнены автоматически.
5. Обновить страницу, открыть историю run и проверить сохранение статусов, событий, вопросов и артефактов.
6. Сохранить обезличенный журнал шагов и результаты с `pass/fail/blocked/not-run`; вариативный текст модели оценивать по инвариантам и артефактам.

| Не пройдено утверждение плана | Ticket execution не стартует. |

## Критерии приёмки

- [ ] Пользователь выполняет основной цикл без команд Codex в терминале после настройки окружения.
- [ ] Есть два зависимых tickets, проверяемые изменения Git, review и retrospective.
- [ ] История и результаты доступны после обновления UI.
- [ ] Реальный HITL подтверждён на указанной версии Codex; пропуск проверки явно блокирует приёмку.

## Ожидаемые артефакты

E2E-сценарий, тестовый репозиторий и журнал доказательств.

Стабильность конкретных скиллов и формата tracker требует наблюдений 08/09; сценарий уточняется по фактическим артефактам.
