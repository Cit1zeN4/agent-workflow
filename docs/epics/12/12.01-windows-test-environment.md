# 12.01. Воспроизводимое Windows-окружение

> Статус: план реализации; проверки не выполнялись.

## Цель

Подготовить чистую конфигурацию, в которой другой исполнитель может воспроизвести сборку и испытания MVP.

## Зависимости и границы

**Зависимости:** 01–11; профиль совместимости из 02.01/02.10. Входит: версии, тестовый Git-репозиторий, локальные данные, команды подготовки и уборки. Не входит: хранение учётных данных в репозитории и результаты E2E.

## Последовательность реализации

1. Зафиксировать фактические версии Windows, Node.js, Git for Windows, Codex CLI и fingerprint схем; расхождения с целевой конфигурацией выделить в отчёте.
2. Подготовить чистый тестовый репозиторий с исходным состоянием, ожидаемыми артефактами и двумя зависимыми tickets после работы скиллов.
3. Разделить локальные тестовые данные, настройки доступа Codex и исходники; секреты не включать в fixtures и логи.
4. Документировать команды установки, сборки, запуска, сброса тестового окружения и сбора обезличенных доказательств.
5. Проверить повторение подготовки с пустой БД и с существующей БД, включая миграции.

## Тестовые сценарии

| Сценарий | Ожидаемый результат |
|---|---|
| Чистая копия проекта | Сборка и автономные проверки запускаются по инструкции. |
| Установлен несовместимый CLI | До E2E появляется объяснимая диагностика совместимости. |
| Повторная подготовка | Не повреждает пользовательский репозиторий и не оставляет старые test worktrees. |

## Критерии приёмки

- [ ] Изолированное окружение создаётся и очищается по инструкции.
- [ ] Версии и профиль совместимости записаны по фактическим выводам команд.
- [ ] Тестовые материалы не содержат секретов или пользовательских исходников.

## Ожидаемые артефакты

Инструкция тестового окружения, fixtures и отчёт о версиях.

## Открытые вопросы

Нужен ли отдельный профиль Codex для E2E, определяется после проверки доступного механизма авторизации.
