# 08.05. Интеграционные проверки скиллов

> Статус: план реализации; код и проверки не выполнялись.

## Цель

Подтвердить вызовы, контекст, HITL и результаты на реальной установке.

## Зависимости и границы

**Зависимости:** 08.01–08.04, 05, 06.

Входит: контролируемые интеграционные сценарии и отчёт о совместимости. Не входит: полный E2E приложения и упаковка этапа 12.

## Последовательность реализации

1. Подготовить чистый тестовый репозиторий и зафиксировать версии Codex и скиллов.
2. Пройти setup, интерактивный grill, spec, tickets, review и retro на контролируемом материале.
3. Собрать manifest, события, ответы, изменения файлов и результат валидатора для каждого вызова.
4. Отметить обязательные сценарии как pass/fail/blocked/not-run с доказательствами; blocked не считать приёмкой.

## Тестовые сценарии

- Подтверждённый вопрос получает ровно один ответ через HITL.
- Неподдерживаемый запрос останавливает выполнение с диагностикой.
- Пустой результат не завершает бизнес-этап.

## Критерии приёмки

- [ ] Реальные запуски, вопросы и результаты подтверждены.
- [ ] Версии и ограничения записаны с доказательствами.
- [ ] Успех turn отличён от успеха этапа.

Для закрытия критериев нужны результаты проверок; наличие плана не означает приёмку.
