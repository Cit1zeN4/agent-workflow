# 08.01. Проверка скиллов и tracker

> Статус: план реализации; код и проверки не выполнялись.

## Цель

Получить наблюдаемый контракт установленной версии скиллов и локального tracker.

## Зависимости и границы

**Зависимости:** 02.01, 05; доступная тестовая установка скиллов.

Входит: версии, способ запуска, структура результатов, интерактивные запросы и fixtures tracker. Не входит: парсер tickets, реализация UI и предположение о неподтверждённой структуре.

## Последовательность реализации

1. Зафиксировать источник, версию или commit установки и тестовый Git-репозиторий.
2. В контролируемом каталоге запустить требуемые скиллы; сохранить обезличенные входы, события, вопросы и изменения файлов.
3. Исследовать результат `/to-tickets`: путь tracker, идентификаторы, зависимости и статусы; создать fixtures только из наблюдаемого формата.
4. Составить матрицу поддержано/не поддержано/не проверено для целевого Codex.

## Тестовые сценарии

- Отсутствующий скилл даёт явную несовместимость.
- Неизвестный tracker блокирует реализацию исполнителя 09.
- Неструктурированный вопрос не объявляется поддержанным HITL.

## Критерии приёмки

- [ ] Для каждого скилла есть проверяемый отчёт с версией и доказательствами.
- [ ] Формат tracker подтверждён fixtures либо записан блокирующий пробел.
- [ ] Неисследованное поведение не помечено поддерживаемым.

Для закрытия критериев нужны результаты проверок; наличие плана не означает приёмку.

## Ожидаемые артефакты

Матрица совместимости, transcripts без секретов и fixtures tracker.
