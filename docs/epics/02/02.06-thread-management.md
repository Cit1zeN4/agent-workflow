# 02.06. Thread Management

> Статус: план реализации; код и runtime-проверки не выполнялись.
> Дата подготовки: 2026-10-22. Целевая версия Codex 0.163.0 взята из исходного проекта и требует фактической проверки.

## Цель

Создавать и продолжать Codex threads с явными идентификаторами и контекстом рабочего каталога.

## Зависимости и границы

**Зависимости:** 02.04 и 02.05.

Входит: низкоуровневые start/resume, mapping и параметры исполнения. Не входит: выбор общей сессии workflow, SQLite, создание worktrees и восстановление активного turn.

## Основания и статус решений

Основание: приложенные AI-Development-Workflow-Orchestrator.md и 02-codex-runtime-integration.md, а также согласованная декомпозиция этапа 02. ADR ниже фиксируют выбранное проектное направление со статусом «предлагается к реализации». Они не являются результатами испытаний. Актуальная документация по ссылкам проверена 2026-10-22; соответствие полей версии 0.163.0 устанавливается в 02.01 и 02.10.

## Архитектурные решения (ADR)

### ADR-02-07 — Thread — контекст runtime, а не workflow run

**Статус:** предлагается к реализации. **Дата:** 2026-10-22.

**Контекст:** Один workflow может использовать несколько сессий; один thread содержит несколько turns.

**Решение:** Адаптер возвращает opaque thread ID, поддерживает явный resume и не создаёт замену молча. Передача cwd и execution policy явная.

**Рассмотренные варианты:** Альтернативы: новый thread на каждый turn; один глобальный thread для всех проектов; скрытый fallback resume → create.

**Последствия:** Session Manager этапа 04 определит повторное использование; ошибка resume остаётся различимой и не теряет историю.

**Пересмотр:** если контракт целевого CLI или real smoke опровергнет предпосылки. Изменение фиксировать новой записью ADR со ссылкой на заменённое решение; не скрывать прежний контекст.

## Последовательность реализации

1. Определить CreateThreadOptions и ResumeThreadOptions на основе узкого DTO 02.05: cwd, выбранная модель и проверенные настройки permissions/sandbox. Не передавать произвольный config из браузера.
2. Проверить cwd: абсолютный существующий каталог, разрешённый Project Manager. Канонизацию Windows-путей и symlinks согласовать с этапом 07; путь не даёт сам по себе security isolation.
3. При thread/start проверить результат, ID и применённые настройки, если они доступны. Сохранить локальный mapping и вернуть opaque ID.
4. При resume использовать только проверенный метод и профиль Codex storage/окружения. Различать неизвестный ID, недоступные данные, несовместимость и auth failure.
5. После restart сначала выполнить 02.04, затем resume. Сохранённый ID — вход от Session Manager; адаптер не ищет workflow в файловом хранилище Codex.
6. Проверить два последовательных turns в одном thread и два разных threads. Контекст должен сохраняться в первом и не смешиваться между вторыми.
7. Timeout thread/start после отправки не превращать в новый start: thread мог уже быть создан. Вернуть неопределённость и диагностические IDs, если известны.
8. Не считать успешный resume доказательством продолжения ранее активного turn либо восстановления ожидающего HITL request.

## Тестовые сценарии

| Сценарий | Ожидаемый результат |
|---|---|
| Thread + два последовательных turns с тестовым маркером | Второй ответ использует маркер без повторного включения в input. |
| Два threads с разными маркерами | Нет ошибочной маршрутизации событий между контекстами. |
| Restart App Server + resume с тем же storage profile | Контекст доступен либо указана конкретная причина невозможности. |
| Несуществующий ID / недоступный cwd / timeout создания | Нет молчаливой новой сессии и автоматического повторного создания. |
| cwd с пробелами, кириллицей, другим диском Windows | Параметры сохранены и валидированы без shell-интерпретации. |

## Критерии приёмки

- [ ] create/resume возвращают валидные runtime IDs и различимые ошибки.
- [ ] Контекст подтверждён последовательными turns и restart/resume на целевом runtime.
- [ ] Политика выбора сессий не встроена в адаптер.
- [ ] Нет скрытого fallback и автоматического повтора создания с неизвестным исходом.
