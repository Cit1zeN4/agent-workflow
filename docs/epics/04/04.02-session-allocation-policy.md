# 04.02. Политика общих и отдельных сессий

> Статус: план реализации; политика не запущена с реальными скиллами.

## Цель

Выбирать одну сессию для связанных этапов и независимую сессию для каждого ticket по явному scope.

## Зависимости и границы

**Зависимости:** 04.01, создание thread из 02.06. Входит: правила выбора/создания session и ограничения повторного использования. Не входит: расписание этапов 06, зависимости tickets 09 и worktree 07.

## Последовательность реализации

1. Определить scope общей сессии run для связанных этапов и ticket scope, содержащий ticket ID.
2. Для нового scope создать session и thread; для повторного связанного этапа использовать существующую пригодную session.
3. Запретить наследование thread между разными tickets и между разными runs, даже если они относятся к одному проекту.
4. При непригодной session вернуть явное решение о новой сессии с контекстом, не выдавая её за продолжение прежней.
5. Сохранить выбор до старта execution, чтобы повторный запрос не создал две session без диагностики.

## Тестовые сценарии

| Сценарий | Ожидаемый результат |
|---|---|
| Два связанных этапа одного run | Используют одну пригодную session/thread. |
| Два отдельных tickets | Получают разные session и thread IDs. |
| Повторный запрос создания одного scope | Не создаёт дубликат незаметно. |

## Критерии приёмки

- [ ] Политика выбора детерминирована и документирована.
- [ ] Ticket sessions не смешивают контекст друг друга.
- [ ] Новая сессия после потери старой помечена как новая, а не «восстановленная».

## Ожидаемые артефакты

Правила allocation, операции выбора и тестовая матрица scopes.

## Открытые вопросы и проверки

Точный набор связанных этапов закрепить совместно с 06 и 08 после проверки того, какой контекст требуется скиллам.
