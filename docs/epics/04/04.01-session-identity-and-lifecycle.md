# 04.01. Идентификаторы и жизненный цикл

> Статус: план реализации; поведение с реальным runtime ещё не подтверждено.

## Цель

Определить устойчивые связи workflow run, agent session и agent execution с opaque идентификаторами Codex.

## Зависимости и границы

**Зависимости:** 01.02, 02.05–02.06 и 03.01–03.02. Входит: модель session, mapping IDs, состояния жизненного цикла и сохранение связи. Не входит: JSON-RPC, политика workflow, восстановление активного turn после сбоя.

## Последовательность реализации

1. Задать внутренние sessionId/executionId и отдельные runtimeThreadId/runtimeTurnId; не использовать thread ID как ID workflow run.
2. Описать создание session, связывание с run или ticket, присоединение execution и закрытие для новых выполнений.
3. Сохранить время, владельца, контекстный scope и runtime IDs через репозитории 03 до публикации состояния потребителям.
4. Определить допустимые состояния session и ошибки отсутствующей или закрытой записи, не скрывая неопределённый исход execution.

## Тестовые сценарии

| Сценарий | Ожидаемый результат |
|---|---|
| Один run с несколькими sessions | Каждая session имеет свой внутренний ID и корректную связь с run. |
| Несколько executions одной session | История сохраняет отдельные execution IDs и порядок. |
| Runtime thread ID меняется или отсутствует | Внутренний ID не переиспользуется ошибочно. |

## Критерии приёмки

- [ ] Run, session, execution и runtime IDs типизированы раздельно.
- [ ] Связи и история переживают рестарт backend.
- [ ] Закрытая или отсутствующая session не получает новый execution молча.

## Ожидаемые артефакты

Session model, mapping и repository operations с тестами связей.

## Открытые вопросы и проверки

Точный момент сохранения runtimeThreadId уточнить по фактическим ответам 02.06; неподтверждённый ID не считать сохранённым thread.
