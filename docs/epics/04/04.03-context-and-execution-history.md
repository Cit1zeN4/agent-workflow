# 04.03. Контекст и история выполнений

> Статус: план реализации; фактическое поведение скиллов ещё не проверено.

## Цель

Передавать минимально необходимый контекст при новом или продолженном turn и сохранять историю executions session.

## Зависимости и границы

**Зависимости:** 04.01–04.02, 02.07, 03.02–03.03. Входит: сбор ссылок на решения и артефакты, trace происхождения контекста, упорядоченная история executions. Не входит: содержание prompts каждого скилла и проверка артефактов этапа 08.

## Последовательность реализации

1. Определить контекстный пакет из задачи run, проверенных артефактов предыдущих этапов и необходимых решений пользователя.
2. Для новой session передать явный контекст; для продолжаемой thread указать только нужные новые данные, не полагаясь безусловно на память модели.
3. Записать, какие документы/версии были переданы конкретному execution, не копируя секреты в журнал.
4. Хранить каждую попытку как отдельный execution с результатом и упорядоченным временем создания.
5. Предоставить чтение истории session для UI и восстановления без вывода ошибочного «успеха» из одного runtime ACK.

## Тестовые сценарии

| Сценарий | Ожидаемый результат |
|---|---|
| Следующий связанный этап | Получает утверждённые результаты предыдущего. |
| Повтор неуспешного этапа | Создаёт новую запись execution; прежняя история сохранена. |
| Запрос истории после рестарта | Порядок и источники контекста восстановлены. |

## Критерии приёмки

- [ ] Для execution видны session, попытка, входной контекст и результат.
- [ ] История одной session читается в порядке создания и не перезаписывается повтором.
- [ ] Секреты не копируются в контекстные диагностические записи без необходимости.

## Ожидаемые артефакты

Контекстный DTO, manifest переданных артефактов и операции истории.

## Открытые вопросы и проверки

Нужный объём контекста уточняется при интеграции скиллов в 08; успешный runtime turn отдельно проверяется на бизнес-результат.
