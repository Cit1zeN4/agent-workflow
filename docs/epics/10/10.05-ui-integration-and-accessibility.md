# 10.05. Интеграция и доступность UI

> Статус: план реализации; код и проверки не выполнялись.

## Цель

Проверить полный пользовательский путь и устойчивость интерфейса на Windows.

## Зависимости и границы

**Зависимости:** 10.01–10.04, 03, 05–09.

Входит: сценарии UI, ошибки, клавиатурная доступность и переподключение. Не входит: полный runtime E2E и упаковка этапа 12.

## Последовательность реализации

1. Проверить путь: проект, setup, run, HITL, утверждение, tickets, review, retro.
2. Проверить обновление страницы и временную потерю SSE во время активного run и ожидающего вопроса.
3. Проверить загрузку, пустые состояния, ошибки API, конфликт ответа и неопределённый исход.
4. Проверить клавиатурную навигацию и видимые подписи форм на основных экранах.
5. Сохранить результат тестового прогона и известные ограничения для этапа 12.

## Тестовые сценарии

- Обновление страницы не теряет ожидающий запрос.
- Конфликт ответа даёт понятное состояние без дубля.
- Основной путь доступен без команд Codex в терминале.

## Критерии приёмки

- [ ] Все обязательные экраны связаны в один сценарий.
- [ ] UI после reconnect согласован с backend.
- [ ] Ошибки и доступные действия понятны пользователю.

Для закрытия критериев нужны результаты проверок; наличие плана не означает приёмку.

## Ожидаемые артефакты

UI test scenarios, acceptance report и перечень ограничений.
