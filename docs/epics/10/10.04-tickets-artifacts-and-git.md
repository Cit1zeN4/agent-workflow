# 10.04. Tickets, артефакты и Git

> Статус: план реализации; код и проверки не выполнялись.

## Цель

Показать результаты workflow и проверяемый след каждого ticket.

## Зависимости и границы

**Зависимости:** 08.04, 09.01–09.04, 10.02.

Входит: список tickets и зависимостей, артефакты, проверки, diff, commits и retrospective. Не входит: чтение tracker, валидация файлов и Git-операции backend.

## Последовательность реализации

1. Показать tickets со статусом, зависимостями, причиной блокировки и историей попыток.
2. Отображать связанные артефакты этапов с безопасной выдачей через API.
3. Показать результаты проверок, Git diff, ветку и commit metadata с явным отсутствием commit.
4. Показать итог code review и retrospective в контексте run.
5. Не интерпретировать произвольные пути из tracker как URL для прямого доступа к файлам.

## Тестовые сценарии

- Зависимый ticket показывает причину блокировки.
- Отсутствующий commit отображается как отсутствие данных.
- Diff и артефакты относятся к выбранному run/ticket.

## Критерии приёмки

- [ ] Пользователь видит план, ход и итог каждого ticket.
- [ ] Артефакты и Git-данные связаны с правильным execution.
- [ ] Данные выдаются через локальный API с проверкой путей.

Для закрытия критериев нужны результаты проверок; наличие плана не означает приёмку.
