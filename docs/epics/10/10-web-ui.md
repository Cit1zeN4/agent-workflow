# 10. Web UI

## Цель

Дать одному локальному пользователю возможность пройти весь workflow и принять необходимые решения в браузере.

## Содержание

- Экраны проектов, настройки скиллов, создания и истории runs, текущего этапа и tickets.
- Отображение событий агента, ошибок, ожидающих HITL-запросов и результатов этапов.
- Формы ответа, разрешения и утверждения; управление паузой, продолжением, отменой и повтором.
- Просмотр артефактов, проверок, Git diff и итогов retrospective.

## Критерии приёмки

- Пользователь подключает репозиторий, настраивает скиллы, создаёт run и проходит контрольные точки без команд Codex в терминале.
- Текущий статус и новые события обновляются через SSE; после обновления страницы интерфейс показывает сохранённое состояние.
- Все поддерживаемые типы HITL-запросов доступны и не позволяют отправить один ответ дважды без явной ошибки.
- UI показывает источник ошибки, следующий допустимый шаг и результаты завершённых этапов; операции выполняются через локальный API.

**Зависимости:** 03, 05–09. **Результат:** рабочий веб-интерфейс полного сценария.
