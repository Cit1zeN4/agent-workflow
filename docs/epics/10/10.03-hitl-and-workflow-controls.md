# 10.03. HITL и управление workflow

> Статус: план реализации; код и проверки не выполнялись.

## Цель

Показать все поддерживаемые запросы к человеку и допустимые действия над run.

## Зависимости и границы

**Зависимости:** 05, 06, 10.02.

Входит: формы ответов, разрешения, утверждения и действия паузы/продолжения/отмены/повтора. Не входит: политика разрешений и backend-переходы.

## Последовательность реализации

1. Получать ожидающие запросы из сохранённого состояния и обновлять их событиями.
2. Для подтверждённых типов построить текстовый, одиночный, множественный и permission интерфейсы; неподдерживаемый тип показывать как блокирующую диагностику.
3. Отправлять ответ с request ID и ожидаемой версией состояния; обрабатывать conflict без повторной отправки.
4. Показывать только действия run, разрешённые его текущим состоянием.
5. Отдельно отображать утверждение плана до tickets.

## Тестовые сценарии

- Двойной ответ получает явный conflict.
- Отказ в разрешении виден в истории.
- Недопустимая кнопка не создаёт переход.
- План без утверждения не запускает tickets.

## Критерии приёмки

- [ ] Каждый подтверждённый тип HITL имеет доступную форму.
- [ ] Ответы и действия отображают фактический backend-результат.
- [ ] Опасное действие не подтверждается молча.

Для закрытия критериев нужны результаты проверок; наличие плана не означает приёмку.
