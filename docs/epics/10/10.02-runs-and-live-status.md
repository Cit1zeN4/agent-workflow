# 10.02. Runs и живое состояние

> Статус: план реализации; код и проверки не выполнялись.

## Цель

Создавать и наблюдать workflow runs с сохранённым состоянием и потоком событий.

## Зависимости и границы

**Зависимости:** 03, 06, 07.

Входит: создание run, история, текущий этап, timeline событий и SSE. Не входит: машина состояний, хранение и SSE backend.

## Последовательность реализации

1. Реализовать создание run для выбранного проекта с описанием задачи.
2. Показывать историю и детальную страницу run из сохранённого snapshot.
3. Подключить SSE и обновлять timeline по идентификаторам событий; при разрыве переподключаться по контракту 03.
4. После обновления страницы сначала загрузить snapshot, затем продолжить поток без потери значимых событий.
5. Показать текущий этап, execution, состояние ожидания и источник ошибки.

## Тестовые сценарии

- Обновление страницы сохраняет тот же статус и историю.
- Разрыв SSE завершается согласованным переподключением.
- Повторное событие не дублирует строку timeline.

## Критерии приёмки

- [ ] Run можно создать и открыть через UI.
- [ ] Статус совпадает с сохранённым backend-состоянием.
- [ ] Ошибки показаны с допустимым следующим шагом.

Для закрытия критериев нужны результаты проверок; наличие плана не означает приёмку.
