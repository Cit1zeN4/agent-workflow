# 03.05. Проверка перезапуска и доставки

> Статус: план реализации; испытаний на Windows пока нет.

## Цель

Подтвердить долговечность записей, миграции и согласованность потока после рестарта backend.

## Зависимости и границы

**Зависимости:** 03.01–03.04. Входит: проверки сохранности, failure injection транзакций, переподключение SSE и отчёт. Не входит: реальное продолжение Codex thread и решение судьбы активного execution этапа 11.

## Последовательность реализации

1. Создать fixture со связанными проектом, run, этапом, session, execution, запросом и событиями.
2. Перезапустить процесс backend и проверить связи, порядок истории и курсор последнего события.
3. Внедрить ошибки записи и убедиться, что состояние и событие откатываются вместе.
4. Отключить и подключить SSE-клиент во время новых записей; проверить snapshot и replay.
5. Составить отчёт pass/fail/not-run с конфигурацией SQLite, Windows и логами без секретов.

## Тестовые сценарии

| Сценарий | Ожидаемый результат |
|---|---|
| Рестарт после commit | Все объекты и события доступны. |
| Рестарт после rollback | Частичного перехода нет. |
| Клиент пропустил несколько событий | Получает их по курсору или новый снимок с явным сигналом. |

## Критерии приёмки

- [ ] Все обязательные сценарии имеют фактический результат и evidence.
- [ ] Не обнаружено потери связей, событий или частичных переходов.
- [ ] Неизвестный исход активного исполнения не помечается успешным только из-за сохранённого журнала.

## Ожидаемые артефакты

Fixtures, автоматические тесты и отчёт проверки перезапуска.

## Открытые вопросы и проверки

Сценарии сбоя runtime и восстановления команд должны быть добавлены на этапе 11.
