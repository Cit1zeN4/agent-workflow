# 03.02. Репозитории и атомарные переходы

> Статус: план реализации; транзакции ещё не проверялись.

## Цель

Дать доменным модулям безопасные операции записи и чтения без прямого доступа к таблицам из UI или runtime.

## Зависимости и границы

**Зависимости:** 03.01, базовые контракты 01.02. Входит: repository interfaces, транзакции, проверка ожидаемого состояния и устойчивые ошибки записи. Не входит: решение, разрешён ли конкретный переход workflow или ответ пользователя.

## Последовательность реализации

1. Определить операции создания и чтения проектов, runs, stages, sessions, executions и запросов в пределах известных контрактов.
2. Для смены состояния принимать ожидаемую версию или текущее состояние и выполнять compare-and-set в транзакции.
3. Записывать новое состояние и связанное доменное событие атомарно через общий transactional writer; событие не публиковать до commit.
4. Возвращать различимые NotFound, Conflict и StorageFailure; retry при неизвестном результате записи не делать автоматически.

## Тестовые сценарии

| Сценарий | Ожидаемый результат |
|---|---|
| Смена состояния и событие | Сохранены вместе. |
| Ошибка перед commit | Ни состояние, ни событие не видны. |
| Две записи с одной ожидаемой версией | Успешна одна; вторая получает конфликт. |

## Критерии приёмки

- [ ] Состояние и соответствующее событие меняются атомарно.
- [ ] Конфликт не превращается в повторное выполнение действия.
- [ ] Потребители используют репозитории, а не SQL в бизнес-модулях.

## Ожидаемые артефакты

Repository interfaces и реализации, транзакционные проверки.

## Открытые вопросы и проверки

Точный набор доменных команд расширяется при реализации 04–09; атомарный контракт сохраняется.
