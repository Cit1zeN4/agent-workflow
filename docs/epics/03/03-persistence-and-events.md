# 03. Persistence & Event System

## Цель

Сохранять ход выполнения и предоставлять упорядоченный поток событий для UI и восстановления.

## Содержание

- Ввести SQLite-схему для проектов, runs, этапов, sessions, executions, HITL-запросов и событий.
- Определить транзакционные операции смены состояния и миграции схемы.
- Записывать структурированные события с идентификаторами, временем и связью с run/execution.
- Предоставить получение текущего состояния и поток обновлений через SSE с повторным подключением.

## Критерии приёмки

- После перезапуска backend сохранённые объекты и события доступны без потери связей.
- Изменение состояния и соответствующее событие фиксируются атомарно; ошибка записи не оставляет частичный переход.
- Клиент после отключения получает актуальное состояние и не теряет значимые события при повторном подключении.
- Миграции применяются к новой и существующей базе; чувствительные данные не попадают в диагностический журнал без необходимости.

**Зависимости:** 01. **Результат:** схема SQLite, репозитории и SSE-контракт.
