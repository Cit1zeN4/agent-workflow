# 03.04. Снимки состояния и SSE

> Статус: план реализации; переподключение клиентов ещё не проверено.

## Цель

Предоставить UI согласованное текущее состояние и поток последующих событий с возобновлением по курсору.

## Зависимости и границы

**Зависимости:** 03.02–03.03, локальный API 01.03. Входит: endpoint снимка, SSE, Last-Event-ID или эквивалентный курсор, лимиты доставки. Не входит: пользовательские экраны этапа 10 и сверка runtime этапа 11.

## Последовательность реализации

1. Сформировать снимок run со связанными этапами, sessions, executions и запросами согласно правам локального пользователя.
2. Определить согласованную точку чтения: snapshot возвращает курсор, от которого можно догрузить последующие события без зазора.
3. Реализовать SSE с ID постоянного журнала, начальной догрузкой после курсора и доставкой новых записей после commit.
4. Ограничить очереди медленных клиентов, heartbeat и число соединений; разрыв объяснять так, чтобы клиент повторил загрузку снимка при устаревшем курсоре.

## Тестовые сценарии

| Сценарий | Ожидаемый результат |
|---|---|
| Событие между snapshot и SSE connect | Клиент его получает. |
| Разрыв соединения | Переподключение продолжает с последнего ID без потери значимого события. |
| Медленный клиент | Ограничение памяти с видимой необходимостью повторного чтения. |

## Критерии приёмки

- [ ] Snapshot и поток имеют согласованный курсор.
- [ ] Повторное подключение не пропускает значимые события.
- [ ] SSE не публикует откатившуюся транзакцию.

## Ожидаемые артефакты

Контракт snapshot/SSE, endpoints и тесты разрыва соединения.

## Открытые вопросы и проверки

Форму клиентских DTO согласовать с 10; семантику восстановления execution определяет 11, а не успешное SSE-подключение.
