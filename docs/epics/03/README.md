Пять заданий на устойчивое состояние и доставку событий. Статус: план реализации; схема, код и проверки ещё не созданы. Основание: [требования](../../project.md), [общий эпик](03-persistence-and-events.md) и контракт событий [02.05](../02/02.05-runtime-adapter-contracts.md).

Схема 03.01 задаёт место для объектов следующих этапов, но не присваивает этапу 03 их бизнес-политику. Для изменения состояния и записи события нужен один транзакционный путь. Runtime sequence из 02 имеет порядок только внутри поколения процесса; постоянный курсор SSE определяет этап 03. Replay и надёжное восстановление исполнения — разные задачи: после рестарта UI читает состояние здесь, а судьбу незавершённого действия определяет 11.
