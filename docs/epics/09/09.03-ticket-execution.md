# 09.03. Исполнение ticket

> Статус: план реализации; код и проверки не выполнялись.

## Цель

Запускать каждый утверждённый ticket в отдельной session и сохранять попытки.

## Зависимости и границы

**Зависимости:** 04, 06, 07, 08.03, 09.02.

Входит: создание session/execution, запуск `/implement`, статусы попыток и связь с workspace. Не входит: управление Codex-процессом, планирование зависимостей и Git review.

## Последовательность реализации

1. Получить готовый ticket и неизменяемый snapshot его входов из утверждённого плана.
2. Создать отдельную session для ticket и выбрать согласованный worktree.
3. Запустить `/implement` через адаптер скиллов; записать execution, входы и события.
4. По завершении сохранить итог попытки; повтор создавать новой попыткой, не перезаписывая историю.
5. Не начинать следующий ticket до проверенного исхода текущего.

## Тестовые сценарии

- Два tickets имеют разные session IDs.
- Повтор не стирает первую попытку.
- Неопределённый исход не запускается автоматически повторно.

## Критерии приёмки

- [ ] Каждый ticket связан с session, попытками и execution.
- [ ] Отказ/сбой оставляет зависимые tickets заблокированными.
- [ ] Run не теряет историю после перезапуска.

Для закрытия критериев нужны результаты проверок; наличие плана не означает приёмку.
