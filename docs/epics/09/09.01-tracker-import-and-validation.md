# 09.01. Чтение и проверка tracker

> Статус: план реализации; код и проверки не выполнялись.

## Цель

Читать подтверждённый формат локального tracker и получать типизированный набор tickets.

## Зависимости и границы

**Зависимости:** 08.01, 08.04, 07.

Входит: парсер подтверждённого формата, проверка идентификаторов, ошибок и происхождения файла. Не входит: исследование формата скиллов, граф планирования и запись изменений tracker.

## Последовательность реализации

1. Использовать только fixtures и спецификацию, полученные в 08.01.
2. Прочитать tracker из допустимого workspace; сохранить fingerprint источника и версию формата.
3. Проверить уникальность IDs, обязательные поля, ссылки на зависимости и корректность путей.
4. Неизвестный или изменённый формат отклонять с указанием проблемной записи.

## Тестовые сценарии

- Дубликат ID отклоняется до запуска агента.
- Отсутствующая зависимость отклоняется с ID источника.
- Неизвестный формат не принимается молча.

## Критерии приёмки

- [ ] Парсер воспроизводимо читает реальные fixtures.
- [ ] Ошибки указывают запись и причину.
- [ ] Ни один ticket не запускается при невалидном tracker.

Для закрытия критериев нужны результаты проверок; наличие плана не означает приёмку.

## Ожидаемые артефакты

Типизированный reader, fixtures и отчёт о несовместимости.
