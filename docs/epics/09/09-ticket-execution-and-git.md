# 09. Ticket Execution & Git

## Цель

Выполнять утверждённые implementation tickets по зависимостям и сохранять проверяемый след изменений в Git.

## Содержание

- Читать локальный tracker, проверять идентификаторы и граф зависимостей, определять последовательность.
- Выполнять ticket в отдельной session и согласованном рабочем пространстве.
- Сохранять статусы, результаты проверок, diff и сведения о commits.
- Запретить несанкционированные push/merge и непреднамеренные изменения основной ветки.

## Критерии приёмки

- На наборе из двух зависимых tickets второй не запускается до успешного завершения первого и утверждения плана.
- Цикл зависимостей или отсутствующая задача обнаруживаются до запуска агента.
- Для каждого ticket доступны session, попытки выполнения, итог, проверки, diff и commit metadata (если commit создан).
- Отказ или сбой ticket блокирует зависимых; изменения остаются в рабочей ветке, push и merge требуют отдельного разрешения.

**Зависимости:** 04, 06–08. **Результат:** исполнитель tickets и Git-история.
