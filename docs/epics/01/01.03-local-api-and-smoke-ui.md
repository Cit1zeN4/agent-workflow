# 01.03. Локальный API и проверочная страница

> Статус: план реализации; сетевые ограничения ещё не проверены.

## Цель

Проверить связь браузера и backend через минимальный локальный API без доступа к системным командам.

## Зависимости и границы

**Зависимости:** 01.01–01.02. Входит: локальная конфигурация прослушивания, простой endpoint доступности, минимальная страница и обработка ошибки связи. Не входит: API проектов, HITL, SSE и полноценные экраны этапа 10.

## Последовательность реализации

1. Выбрать явный loopback-адрес и порт либо предсказуемое правило его выбора; запретить случайное прослушивание внешних интерфейсов.
2. Реализовать endpoint доступности с минимальным ответом без секретов и внутренних путей.
3. Подключить UI к endpoint через настроенную локальную базу API и показать успешное/ошибочное состояние.
4. Проверить запуск, обновление страницы, выключенный backend и попытку обращения извне локального интерфейса.

## Тестовые сценарии

| Сценарий | Ожидаемый результат |
|---|---|
| UI и backend запущены | Страница получает корректный ответ. |
| Backend остановлен | UI показывает ошибку без зависания. |
| Проверка bind address | API доступен на loopback и не слушает внешний интерфейс. |

## Критерии приёмки

- [ ] UI получает ответ от backend без ручной правки исходников.
- [ ] Ошибка подключения видна пользователю.
- [ ] Локальный API не содержит endpoint произвольного выполнения команд и слушает только loopback.

## Ожидаемые артефакты

Минимальный endpoint, проверочная страница и конфигурация локального запуска.

## Открытые вопросы и проверки

Правило порта и стратегия доступа локального браузера должны быть описаны до расширения API на последующих этапах.
