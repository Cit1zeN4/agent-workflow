# 01.01. Структура приложения и команды

> Статус: план реализации; фактическая сборка не проверена.

## Цель

Создать минимальную структуру React + TypeScript и Node.js + TypeScript с повторяемыми командами разработки.

## Зависимости и границы

**Зависимости:** нет. Входит: исходные проекты, общие команды установки, запуска, проверки и сборки. Не входит: бизнес-логика, подключение Codex, SQLite и упаковка MVP этапа 12.

## Последовательность реализации

1. Зафиксировать структуру frontend, backend и общих контрактов, а также поддерживаемый менеджер пакетов и версии инструментов как проектное решение.
2. Создать минимальные точки входа UI и backend с типизацией, не вводя будущие доменные функции.
3. Добавить единые команды установки, разработки, статической проверки и production build; определить место для автоматических тестов.
4. Проверить запуск в чистой копии на целевой Windows-среде и записать фактически использованные версии Node.js и инструментов. Числа из исходного проекта считать целевыми до проверки.

## Тестовые сценарии

| Сценарий | Ожидаемый результат |
|---|---|
| Чистая копия, установка по инструкции | Зависимости ставятся без ручной правки файлов. |
| Сборка и проверка обоих проектов | Команды завершаются без ошибок и работают повторно. |
| Отсутствует обязательный инструмент | Команда даёт понятную диагностику. |

## Критерии приёмки

- [ ] UI и backend запускаются командами проекта на Windows.
- [ ] Сборка и статические проверки проходят в чистой копии.
- [ ] Использованные версии и команды зафиксированы на основании запуска, а не предположения.

## Ожидаемые артефакты

Структура проектов, scripts и краткая инструкция для разработчика.

## Открытые вопросы и проверки

Выбор менеджера пакетов и точных команд фиксируется при реализации; этот план не объявляет их проверенными.
