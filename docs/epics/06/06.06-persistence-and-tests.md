# 06.06. Сохранение и интеграционные проверки

## Цель

Подтвердить, что переходы workflow сохраняются и воспроизводимы при нормальном ходе и ошибках.

## Зависимости и границы

Зависит от 06.01–06.05 и 03. Полное восстановление после смерти backend относится к 11, полный пользовательский E2E — к 12.

## Последовательность реализации

1. Проверить транзакции state + event для всех команд и verdict.
2. Запустить детерминированные тесты с fake runtime, session и валидаторами: happy path, fail, pause, cancel, retry, approval.
3. Проверить конкурентные команды, поздние события и restart чтения сохранённого run.
4. Сравнить восстановленное состояние и историю событий с ожидаемой таблицей переходов.
5. Подготовить acceptance report с ссылками на тесты и явно не покрытые real runtime сценарии.

## Тестовые сценарии

| Сценарий | Ожидаемый результат |
|---|---|
| Сбой записи в момент перехода | Нет состояния без события или события без состояния. |
| Повторное открытие сохранённого run | Текущий stage и история attempt совпадают. |
| Два конкурентных resume/retry | Не появляется два активных execution. |

## Критерии приёмки

- [ ] Все переходы из 06.01 покрыты тестами.
- [ ] Атомарность и защита от дублей подтверждены.
- [ ] Состояние после restart соответствует журналу.
- [ ] Неизвестный исход остаётся отдельным состоянием.

## Ожидаемые артефакты

Интеграционные тесты, фикстуры событий и acceptance report.
