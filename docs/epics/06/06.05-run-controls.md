# 06.05. Пауза, отмена и повтор

## Цель

Обеспечить предсказуемые команды управления run без потери истории и опасного повторного исполнения.

## Зависимости и границы

Зависит от 06.01–06.04 и interrupt 02.08. Пауза блокирует последующие переходы; судьбу активного turn определяет отдельная политика. Проверка после сбоя — 11.

## Последовательность реализации

1. Определить семантику pause, resume, cancel и retry для idle, active, awaiting-user и terminal состояний.
2. На pause прекратить автоматический старт следующего этапа. Если нужна остановка активного turn, отправить interrupt через 02 и дождаться подтверждения/неопределённого исхода.
3. На cancel закрыть run только после урегулирования активного execution; поздние события не должны вернуть его в running.
4. Retry разрешать лишь для завершённой или явно урегулированной попытки; новая attempt получает новый ID и сохраняет предыдущую историю.
5. Сохранять команду и итог атомарно; повторный запрос с тем же идентификатором не создаёт вторую попытку.

## Тестовые сценарии

| Сценарий | Ожидаемый результат |
|---|---|
| Pause перед автопереходом | Следующий stage не запускается. |
| Cancel при активном turn | Конечное состояние зависит от подтверждённого исхода, неизвестный исход не скрывается. |
| Retry failed stage | Новая attempt создана, прежняя история сохранена. |

## Критерии приёмки

- [ ] Команды имеют явные предусловия и ответы.
- [ ] Pause и cancel не подменяются мгновенным завершением runtime.
- [ ] Retry не дублирует активный execution.
- [ ] Поздние события не нарушают terminal-статус.

## Ожидаемые артефакты

Контракт команд, таблица гонок и тесты управления run.

## Открытые вопросы

Должна ли пауза прерывать активный turn или только запретить следующий? Выбрать и явно показать пользователю.
