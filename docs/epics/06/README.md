# Этап 06 — Workflow Engine

Шесть самостоятельных заданий на реализацию. Основание: [исходный эпик](06-workflow-engine.md) и [требования проекта](../../project.md). Это план, а не подтверждение работающего workflow.

| Подэтап | Задание |
|---|---|
| 06.01 | [Состояния и команды run](06.01-run-state-contract.md) |
| 06.02 | [Последовательность этапов](06.02-stage-orchestration.md) |
| 06.03 | [Проверка завершения этапа](06.03-stage-completion-gates.md) |
| 06.04 | [Утверждение плана](06.04-plan-approval-gate.md) |
| 06.05 | [Пауза, отмена и повтор](06.05-run-controls.md) |
| 06.06 | [Сохранение и интеграционные проверки](06.06-persistence-and-tests.md) |

Порядок: сначала контракт 06.01; затем оркестрация 06.02 и проверки 06.03; затем контрольная точка 06.04 и команды 06.05; в конце интеграция 06.06. Контракты переходов согласовать с 03–05 до реализации.

Границы: runtime сообщает итог turn через 02, Session Manager 04 управляет сессией, HITL 05 принимает решения, 08 проверяет артефакты скиллов, 09 исполняет tickets. Этап 06 принимает бизнес-решение о статусе run и запуске следующего этапа. Ни ACK, ни завершённый turn сами по себе не открывают следующий этап. Восстановление спорных исходов после сбоя — 11.

Критерии каждого файла закрываются тестами и фактическими результатами, а не наличием документа.
